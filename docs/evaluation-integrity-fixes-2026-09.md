# 2026-09 评测完整性修复

这些修复针对评测系统的行为，不代表任何模型自动获得更高或更低的成绩。历史生成结果、Judge 记录和测试数据不在本次源码修改范围内。

## 已修复

| 问题 | 影响 | 修复与回归验证 |
| --- | --- | --- |
| SSE 最后一包 `choices: []` 的 usage 被跳过 | 输入 token 变成 0，输出退回字符估算，思考消耗漏计 | 在读取 choices 前处理 usage/timings；保存供应商 reasoning_tokens；总生成量不重复加思考量 |
| 供应商无 usage 时只估算正文 | 低估推理模型开销 | 估算思考与正文的合计，并写入 `tokenUsageSource: estimated`；这不是 tokenizer 精确计数，缺失输入不能恢复 |
| reasoning 被当作空正文的替代答案 | 模型没有交付最终答案也进入普通判分 | 保留两个独立通道；空最终答案进入已有的空输出/预算耗尽路径 |
| 流结束和中止处理不完整 | 最后一行漏读、DONE 后继续等待、约束兼容重试丢失思考上限 | EOF 处理残留事件；收到 DONE 结束；中止时 cancel reader；stream_options 回退继承上限 |
| 首 token 计时忽略 reasoning | 推理模型 TTFT 偏大，生成时段与输出量不一致 | 第一个思考或正文增量开始计时 |
| Judge 输入硬裁剪为 4,000 字符 | 多文件补丁后半段不可见，完整性判断证据不足 | 发送完整答案；不在不告知的情况下裁剪。超过供应商上下文会明确失败并要求补评 |
| Judge JSON 无法解析时制造全零评分 | 通讯/协议问题被混入模型能力分 | 无法解析、缺失必需子分、越界子分直接失败；finish_reason=length 的 Judge 不接受为有效评分；沿用保留生成结果、临时确定性分的降级路径 |
| Judge maxTokens 写死 | 设置中的生成预算不生效 | 尊重 Judge defaultParams.maxTokens，未设置才用 8,192 |
| 质量报告不提示 Judge 失败、截断题号为 ?、补跑后残留旧提示 | 未完成评分被当作正式完整成绩 | 从保存结果计算失败数量、环境隔离和真实题号；补评/补跑刷新；详情页显示告警，AI 报告使用即时诊断 |
| RM-CN-032 标准答案错误 | 正误判断依据错误 | 按题设计算 `(25000-4500-5000-2000-1000)*20%-1410=1090` |
| 数值题容差单位不明确 | tolerance=1 被解释为 100% 相对误差 | 增加显式 absolute 模式；8 道数值数学题声明绝对容差；旧自定义配置保留相对模式兼容 |
| DE-CN-004 prompt/评分结构矛盾 | 要求数组，评分却取根对象字段 | 明确 order_id/items_count/items 根对象契约，增加价格、评分、评论的逐商品检查 |
| CP-L4-RS-001 无锁文件却 fetch --locked | 原始工程依赖预检失败，模型无法获得有效测试结果 | 原始工作区允许 cargo fetch 生成锁文件；不放宽执行测试断言 |

## 版本与生效

- 8 道数学题：RM-CN-001、003、004、023、025、031、032、034，题目版本 2.0.1。
- DE-CN-004：2.0.1；CP-L4-RS-001：1.2.1。均重新计算 canonical hash。
- 源码题库与数据库题库相互独立。构建后需重启后端；题库需选择性同步上述 10 题才能用于新评测，不能用清空题库或覆盖全部题库的方式部署。
- 若有暂停的旧评测，先决定是否继续旧口径，再同步修订题库。已有成绩不会因构建源码而自动重算。

## 历史结果的恢复边界

- Judge 故障和旧输入裁剪：可使用保存的完整答案仅补评 Judge，无需重新生成模型答案。输入被裁剪不等于 Judge 自身输出被截断，不能根据 `truncated` 单词做统计。
- 数学题：保存答案可按新标准离线重算，但必须留存新旧评分版本，不能把新评分直接冒充原始成绩。
- DE-CN-004：输出契约已改变。旧数组答案不能直接套用新对象契约处罚；正式跨模型比较应统一题目版本补测，或另行制定兼容旧 prompt 的复核标准。
- Rust 预检：修复后仍须实际执行工程测试，不能凭依赖预检修复推定模型通过。
- token：未来调用保留 usage 来源；历史漏掉的供应商 usage 无法由源码修复恢复。字符估算、重新分词和供应商账面 token 不应混为同一精确口径。
- 本次不重写模型报告及总分、不调用模型/Judge、不提交用户评测数据。
