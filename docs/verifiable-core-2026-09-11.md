# 可验证核心评分 v1

## 本次改变

新开发评测的主分数不依赖Judge。复用已讨论的12道数学挑战题与8道封闭材料幻觉题，新增可直接导出题包、接收保存答案并计算维度分数的离线入口。未降低题目难度，未重写历史答案，未改变题面和旧验证器。

本入口独立于现有线上全维度评测；**没有把生产系统全局切换到新口径**。旧成绩、报告、数据库及HE-001各版本试跑保留。未来新试测使用此入口；不把新旧口径拼接为可直接比较的榜单。

## 评分约定

- 幻觉题：每一小问只有“答案值、证据状态、充分且相关的引用”全部通过才得分。题分为通过小问比例乘100，再按题等权计算维度均分。不是把答案与引用独立相加；错误断言不能靠引用得半分，也不能靠全部拒答拿满分。
- 数学题：题目明确要求的答案、约束、证书均通过才得100分，否则0分；旧的分项检查保留用于定位错误，但不冒充推理过程得分。接受既有验证器支持的精确等价数值与等价合法构造。没有形式化验证的自由文本证明不在这一主评分入口。
- HE-001等开放式分析不进入核心计划与分母。Judge只可作为按需诊断，保留原始意见；自动调用关闭、评分权重为0，不生成主分数。用户认可题面不等于专业答案核验。
- 完整返回但格式非法记0，并显示格式失败；缺失、截断、环境错误、验证器自身失败记为未测量，不当作能力0分。只要该维度存在未测量题，维度分数为null，明确列出缺口，不对已完成子集给出冒充全量的均分。
- 一份提交绑定一个runId、modelId和完整计划，每题只能有一个明确选定的结果。重复题、未知题、陈旧题面哈希、陈旧评分合约一律拒绝；不取最高分、不隐式选择历史重试。需要重试时由调用方明确整理新提交及出处，旧提交和评分文件不覆盖。
- 不计算数学和幻觉的混合总分，不伪造跨维度权重。这里的维度分数均为开发题集测量，不自动提升为正式能力总分。

## 直接使用

从项目根目录执行（只读本地输入、写新输出，不联网）：

```powershell
pnpm --filter server exec tsx ../../packages/core/src/scripts/verifiable-core.ts export reports/verifiable-core-2026-09-11-v1
pnpm --filter server exec tsx ../../packages/core/src/scripts/verifiable-core.ts grade reports/verifiable-core-2026-09-11-v1 answers.json new-result.json
```

`candidate-questions.json`是唯一考生侧导出：包含题面、id和questionHash，不包含参考答案或预设标签。`coordinator/`里的参考答案只用于本地工程核验，不能交给被测模型。题包中未生成Judge请求。

`answers.json`结构如下。contractHash和questionHash须从题包复制，每道题按实际完成状态填写；不得把截断或环境错误改成completed来取得成绩。

```json
{
  "contractHash": "题包合约哈希",
  "runId": "本次运行标识",
  "modelId": "本次被测模型标识",
  "answers": [
    {
      "id": "HC3-001",
      "questionHash": "该题哈希",
      "outcome": "completed",
      "output": "原始模型回答字符串"
    }
  ]
}
```

outcome只接受completed、truncated、environment_error；未运行的题不填。提交字段不接受judgeScore等旁路加分。题包与关键验证器源代码冻结；修改后须另导出新包，不得静默重评旧包。所有导出、结果文件拒绝覆盖。

## 验证与限制

新增测试覆盖答案错误但引用正确、答案正确但证据缺失/捏造、全拒答、冲突与信息不足混淆、错证书、格式错误、截断、环境错误、缺题、重复结果、篡改题包和Judge分数注入。保留v0.6真实失败Judge响应作回归，确认它只能进入辅助记录且不改变原始标签。

数学验证器已有枚举、递推或独立实现交叉核验；这些仍可能共享题意误解。幻觉题仍依赖作者维护的封闭材料答案和可接受证据链，**程序可复现不代表作者金标必然正确**。20道题是首版核心试测，不代表对开放生成、长文幻觉或实际场景的完整覆盖。难度、区分度和推广性尚待真实模型测量，本次不启动模型或Judge调用。
